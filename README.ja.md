# Language Suite

[English](README.md) | **日本語**

AI の先生と一緒に語学を練習するためのアプリです。無料のローカルモデルを使って
自分のパソコンの中だけで動かすことも、クラウドの AI サービスを使うこともできます。

**このような形でソフトをインストールするのが初めての方へ:** まず
[かんたんガイド](USER_MANUAL.ja.md)をお読みください。用語の説明から始めて、
専門知識がなくても進められるように、インストールの手順を一つずつ案内しています。

アプリの画面は英語です。この文書では、画面上のボタンや項目の名前を英語のまま
(例: **Settings**)書き、必要に応じて日本語の説明を添えています。

機能は 7 つのセクションに分かれています。

| セクション | 機能 |
|---|---|
| Speaking(話す) | 会話パートナー、就職面接のリハーサル、通訳シミュレーション、スピーチ、シャドーイング(すべて音声) |
| Listening(聞く) | 聴解(読み上げられた文章についての選択式問題) |
| Vocabulary(語彙) | 語彙練習(入力または音声)、単語リスト作成(CSV ほか) |
| Writing(書く) | ディクテーション(入力または手書き)、作文、翻訳(入力・ファイル・手書き) |
| Reading(読む) | 読解(文章についての選択式問題) |
| Grammar(文法) | 文法ドリル(穴埋め、誤文訂正) |
| Progress(進み具合) | 結果の履歴と、復習用の「間違いリスト」 |

## しくみ

アプリには 3 つの「差し込み口」があります。プラグの形さえ合えば何でも
つなげるので、機能を変えずに、それぞれをローカルにもクラウドにもできます。

| 差し込み口 | 役割 | ローカル(無料) | クラウド |
|---|---|---|---|
| 頭脳 | 会話、出題、フィードバック | Ollama | OpenAI 形式の API なら何でも |
| 耳 | 音声を文字にする | パソコン上の Whisper(別途インストール) | OpenAI 形式の文字起こし API |
| 口 | 文字を音声にする | ブラウザーに内蔵の音声(既定) | OpenAI 形式の音声合成 API |

アプリ本体にモデルは含まれていません。モデルと音声エンジンは、それぞれの
ライセンスのもとで別にインストールします。

## どちらの構成を選ぶか

| | ローカル(Ollama) | クラウドサービス |
|---|---|---|
| 費用 | 無料 | 多くは従量課金 |
| プライバシー | すべてパソコンの中にとどまる | 文章が事業者に送られる |
| 必要なもの | VRAM 約 8 GB の GPU(CPU だけでも動くが遅い) | アカウントと API キー |
| 準備の手間 | Ollama を入れてモデル(数 GB)をダウンロード | 設定を 3 行書くだけ |

## インストール Windows 11

### 1. 基本のソフトを入れる

1. **Python 3.11 以降**を <https://www.python.org/downloads/> から入れます。
   インストーラーで **"Add python.exe to PATH"** にチェックを入れてください。
2. **Git** を <https://git-scm.com/download/win> から入れます(選択肢は既定のままで構いません)。

新しい PowerShell ウィンドウで、両方を確認します。

```powershell
python --version
git --version
```

### 2. コードを取得する

```powershell
git clone <リポジトリの URL>
cd language-suite-v1
```

(`git clone` が作ったフォルダーの名前が違う場合は、そのフォルダーに `cd` します。)

### 3. 専用の Python 環境を作る

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

PowerShell が `Activate.ps1` の実行を拒否する場合は、次を一度だけ実行してから
やり直してください。

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

PowerShell のウィンドウを新しく開くたびに、`.venv\Scripts\Activate.ps1` を
もう一度実行する必要があります。

マイクを使う機能のために、ローカルの音声認識も入れておきます(詳しくは
「マイク 音声認識」の節)。

```powershell
pip install -r requirements-voice.txt
```

### 4. 設定ファイルを作る

```powershell
copy .env.example .env
```

`.env` はあなた専用の設定ファイルです。git の対象外なので、共有されることは
ありません。

### 5a. ローカル構成: Ollama

1. <https://ollama.com/download> から Ollama をインストールします。自動で起動し、
   バックグラウンドで動き続けます。
2. モデルをダウンロードします(約 10 GB、最初の 1 回だけ)。

   ```powershell
   ollama pull gemma4:e4b
   ```

3. 動作確認: `ollama run gemma4:e4b "Say hello in Spanish"`

既定の `.env` は最初から Ollama を指しているので、編集は不要です。

グラフィックメモリ(VRAM)ごとのモデルの目安です。あくまで出発点なので、
現在のモデルとサイズは <https://ollama.com/library> で確認してください。

| GPU メモリ | 最初に試すモデル |
|---|---|
| GPU なし / 6 GB 未満 | `gemma4:e2b`(遅く、フィードバックも簡素)。またはクラウドサービス |
| 8 GB | `gemma4:e4b` |
| 12 GB 以上 | `gemma4:12b` |

別のモデルを使うには、`ollama pull <名前>` で取得し、`.env` に
`LLM_MODEL=<名前>` と書きます。

### 5b. クラウド構成: OpenAI 形式のサービス

Ollama は不要です。`.env` をテキストエディターで開き、事業者のドキュメントに
従って次の 3 つを設定します。

```ini
LLM_BASE_URL=<事業者の API アドレス。多くは /v1 で終わる>
LLM_MODEL=<事業者のモデル名>
LLM_API_KEY=<あなた自身のキー>
```

キーは他人に見せないでください。キーを知っている人は、あなたの料金で
サービスを使えてしまいます。

### 6. アプリを起動する

```powershell
python -m uvicorn app.main:app --port 8000
```

ブラウザーで <http://localhost:8000> を開きます。止めるときは PowerShell で
`Ctrl+C` を押します。アプリが待ち受けるのは自分のパソコンだけで、
ネットワークには公開されません。

## インストール macOS

アプリはふつうの Python プログラムなので、Mac でも同じように動きます。
違うのはコマンドだけです。**ただし、この手順は作者が Mac でまだ試して
いません**(「未対応の項目」参照)。うまくいかない手順があれば、issue で
お知らせください。

1. **基本のソフトを入れる。** Python 3.11 以降を
   <https://www.python.org/downloads/> から入れます(Homebrew を使っているなら
   `brew install python`)。Git は Apple のコマンドラインツールに含まれています。
   **ターミナル**を開いて `xcode-select --install` を実行し、両方を確認します。

   ```bash
   python3 --version
   git --version
   ```

2. **コードを取得し、専用の Python 環境を作る。**

   ```bash
   git clone <リポジトリの URL>
   cd language-suite-v1
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   pip install -r requirements-voice.txt    # マイクを使う機能用
   cp .env.example .env
   ```

   ターミナルのウィンドウを新しく開くたびに `source .venv/bin/activate` を
   実行します。環境が有効な間は、`python` と打てば正しい Python が使われます。

3. **ローカル構成: Ollama。** <https://ollama.com/download> から macOS 版を
   ダウンロードして一度開き(メニューバーにアイコンが出ます)、ターミナルで
   次を実行します。

   ```bash
   ollama pull gemma4:e4b
   ollama run gemma4:e4b "Say hello in Spanish"
   ```

   Mac ではシステムとモデルが同じメモリを共有するため、グラフィックメモリでは
   なく全体のメモリ量でモデルを選びます。目安は、8 GB なら最小のモデル
   (`gemma4:e2b`)かクラウドサービス、16 GB なら `gemma4:e4b`、32 GB 以上なら
   より大きいモデルです。Apple シリコン(M1 以降)の Mac は、Intel の Mac より
   ずっと速く動きます。

   クラウドサービスを使う場合は、Windows の手順 5b と同じ設定をします。

4. **アプリを起動**して <http://localhost:8000> を開きます。止めるときは
   ターミナルで `Ctrl+C` を押します。

   ```bash
   python -m uvicorn app.main:app --port 8000
   ```

この文書のほかの部分(Windows 向けの説明)との違いは次のとおりです。

| 項目 | Mac の場合 |
|---|---|
| コマンド | PowerShell の代わりにターミナルを使う。`copy` は `cp`。環境の有効化は `source .venv/bin/activate` |
| ブラウザー | Chrome か Edge を使う。Safari は未確認 |
| 音声 | **システム設定 > アクセシビリティ > 読み上げコンテンツ > システムの声 > 声を管理** で追加し(macOS のバージョンによって名称が少し違います)、ブラウザーを再起動する |
| マイク | **システム設定 > プライバシーとセキュリティ > マイク** でブラウザーを許可する |
| コンテキストウィンドウ | `setx` の代わりに `launchctl setenv OLLAMA_CONTEXT_LENGTH 8192` を実行し、Ollama を終了して開き直す(新しい Ollama アプリでは、アプリ自身の設定画面でも変更できます) |
| 音声認識 | `STT_DEVICE=cpu`(既定)のままでよい。`cuda` は NVIDIA のカード専用 |
| 開発者向けコマンド | PowerShell の `$env:NAME = "1"` は、ターミナルでは `export NAME=1` |

## 2 回目以降の起動と更新

別の日にアプリを起動するには(Windows の場合。Mac では macOS の節にある
有効化コマンドを使います):

```powershell
cd <プロジェクトのフォルダー>
.venv\Scripts\Activate.ps1
python -m uvicorn app.main:app --port 8000
```

Ollama はパソコンと一緒に起動するので、何もする必要はありません。
アプリを新しいバージョンにするには:

```powershell
git pull
pip install -r requirements.txt
```

そのあとアプリを再起動し、ブラウザーが古いファイルを使い続けないように
`Ctrl+F5` でページを読み込み直します。`.env` と、`data/` の中の履歴は
そのまま残ります。

## ローカルモデルの変更と入れ替え

このアプリは特定のモデルに依存していません。`gemma4:e4b` は `.env.example` に
書かれている既定値にすぎず、Ollama で使えるチャットモデルならどれでも
代わりになります。そのモデルの名前が変わったり、Ollama のライブラリから
なくなったり、新しいバージョンに置き換えられたりした場合も、同じ手順で
対応できます。

気づくきっかけ: `ollama pull` が「モデルが見つからない」と答える、または
アプリに "Model ... was not found" と表示される。すでにダウンロードした
モデルはパソコンに保存されているので動き続けます。問題になるのは、
新しくインストールするときだけです。

**1. モデルを探す。** <https://ollama.com/library>(または
<https://ollama.com/search>)を開き、次の点を満たすモデルを探します。

| 確認点 | 見るところ | 理由 |
|---|---|---|
| サイズ | モデルのページにあるダウンロードサイズ。目安として、グラフィックメモリより少し小さいこと | 入りきらないモデルは一部が CPU で動き、非常に遅くなる。(`gemma4:e4b` など一部のモデルは、画像や音声用の部品を含むため、動作に必要な量よりディスク上のサイズが大きい。迷ったら試してみること。`ollama ps` に "100% GPU" と出れば収まっている) |
| 言語 | 説明に "Multilingual"(多言語)とあること。学習する言語が挙がっていればなおよい | 英語しか得意でないモデルもある |
| 画像 | **vision** のラベル | 手書き(ディクテーション、作文、翻訳)と画像の資料に必要。それ以外では不要 |
| 種類 | 汎用のチャットモデル、または "instruct" モデル | コード用、埋め込み用、推論専用のモデルは先生役に向かない |
| ライセンス | モデルのページに表示されているライセンス | ダウンロードは無料でも、利用条件はモデルごとに違う |
| 新しさ | 新しく、よく使われているモデルを選ぶ | 同じサイズなら、新しい小型モデルのほうが明らかに優れている |

モデル名は `gemma4:e4b` のように `系列:サイズ` の形をしています。モデルの
ページの **Tags** に、すべてのサイズとダウンロードサイズが並んでいます。
小型の多言語モデルを出してきた系列には、たとえば Gemma、Qwen、Mistral、
Llama、Phi、Granite があります。名前やバージョンは頻繁に変わるので、
いま何があるかはライブラリで確認してください。

**2. ダウンロードして試す。**

```powershell
ollama pull <名前>
ollama run <名前> "Explain the difference between 'por' and 'para' in two sentences."
ollama show <名前>
```

`ollama show` は、モデルのコンテキスト長、ライセンス、機能(capabilities)を
表示します。手書きを使いたい場合は、そこに "vision" が含まれている必要が
あります。

**3. アプリに伝える。** `.env` に `LLM_MODEL=<名前>` と書いて、アプリを
再起動します。使用中のモデルはページの上部に表示されます。

**4. アプリで確かめる。** 小型モデルで差が出やすいのは、このアプリが頼りに
している 2 点、つまり「指定した言語で書くこと」と「アプリが期待する決まった
形式で答えること」です。語彙練習、文法ドリル、読解を一度ずつ試してください。
"did not return a usable ..." が何度も出る、フィードバックの言語が違う、と
いった場合は、別のモデルか一段大きいサイズを試します。

**5. 片づける。** `ollama list` でインストール済みのモデルと使用容量を確認でき、
`ollama rm <古い名前>` で削除できます。

どのローカルモデルでも十分に動かないパソコンでは、クラウドサービス
(インストールの手順 5b)がもう一つの道です。機能は同じです。

## 設定

画面上部の **Settings** ボタンを押すと小さなパネルが開き、次の項目を
一度だけ設定できます。

| 設定 | 使われるところ |
|---|---|
| Language I am learning(学習する言語) | すべての機能の言語欄に自動で入る |
| My language(自分の言語) | 語彙、単語リスト、通訳、翻訳の「訳す側」の言語 |
| My level(自分のレベル) | すべての機能で難易度があらかじめ選ばれる |
| Feedback and explanations in(フィードバックと説明の言語) | すべての機能で、先生のフィードバックに使う言語。空欄なら自分の言語、それも空欄なら英語 |

設定は入力欄を埋めるだけなので、そのセッションに限って別の値に変えることも
できます。保存先はブラウザーの中だけです。

## コンテキストウィンドウ

モデルが一度に扱える文章の量には限りがあります。これをコンテキストウィンドウと
呼び、トークンという単位で数えます(1 トークンは英語でおよそ 4 分の 3 語、
日本語でおよそ 1 文字)。指示文、あなたの文章、そして答えのすべてが、
この中に収まらなければなりません。

**Ollama は、リクエストが長すぎてもエラーを出しません。黙って一部を
切り捨てます。** その結果、作文の最後の部分を無視したフィードバックや、
文章の半分についてしか出題しない、といった症状が出ます。家庭用のパソコン
(グラフィックメモリ 24 GB 未満)では、Ollama の既定のウィンドウは多くの場合
4,096 トークンです。長い作文、翻訳、設問の多い長文読解は、特に日本語や
中国語ではこれを超えることがあります。

アプリはリクエストごとに大きさを見積もり、収まりそうにないときは注意を
表示します。Windows の Ollama で上限を上げるには:

1. PowerShell で `setx OLLAMA_CONTEXT_LENGTH 8192` を実行する
2. Ollama を終了し(時計の近くのアイコンを右クリックして Quit)、もう一度起動する
3. `.env` に `LLM_CONTEXT_TOKENS=8192` と書いて、アプリを再起動する

モデルが読み込まれている間に `ollama ps` を実行すると、実際に使われている
ウィンドウの大きさがわかります。ウィンドウを大きくすると、そのぶんメモリが
必要です。モデルが急に遅くなったら、グラフィックメモリに収まらなくなった
ということなので、数値を小さくするか、文章を短くしてください。
クラウドサービスの場合は、`LLM_CONTEXT_TOKENS` をそのモデルの上限に合わせるか、
`0` にしてチェックを切ります。

## 会話パートナーと就職面接

モデルと音声で話します。**Conversation**(会話)では、選んだ話題について
先生が相手をします。**Job interview**(就職面接)では、面接官が決まった数の
質問をします。

1. 言語と難易度を選びます。Session prompt(セッションの指示)で、話題
   ("Let's talk about fashion trends" など)や職種を指定します。面接では、
   履歴書や求人票を資料としてアップロードできます。
2. 相手が先に話します。マイクで答えるか(「マイク 音声認識」参照)、
   **Hands-free** にチェックを入れます。**Repeat** は直前の発言をもう一度
   再生します。速度と声は変更できます。
3. セッションを終えると、良かった点と改善点のフィードバックと、会話全体の
   スクリプトが表示されます。どちらもダウンロードできます。

## 語彙練習

一方の言語で単語が表示され、もう一方の言語に訳します。入力する方法
(**Text**)と、声で答える方法(**Voice**)があります。

- 単語は先生が用意するか(話題とレベルを Session prompt に書きます)、
  自分の単語リストのファイルから出題されます。
- 答えは、アプリ自身が「正解とされる訳」と照合します。一致しなかった答えは
  最後に先生に見せ、それでも正しい訳であれば正解として認められます。
- 音声モードでは単語が読み上げられ、あなたが話した答えが解答欄に
  書き込まれます。送信する前に直せます。
- 間違えた単語と飛ばした単語は **Progress > My mistakes** に入り、そこから
  もう一度練習できます。

## ディクテーション

アプリが文章を 1 文ずつ読み上げ、聞こえたとおりに書き取ります。キーボードでも
手書きでもできます(「手書きのディクテーション」参照)。

- 言語、難易度、長さ(約 3 文、6 文、10 文)を選びます。文章は先生が作るか、
  自分の資料から作られます。
- 各文は、Slow(遅い)・Normal(普通)・Fast(速い)の速度で、何度でも再生できます。
- 結果には、文ごとに聞き落とした語や書き方の違う語、正確さ、先生のコメントが
  表示されます。句読点と大文字・小文字は採点されません。

## 通訳シミュレーション

逐次通訳を音声で練習します。話し手の人数を選びます。

| | 1 人(スピーチ) | 2 人(対話) |
|---|---|---|
| 聞くもの | 1 人が 1 つの言語で話すスピーチ | 互いの言語がわからない 2 人が、あなたを介して話す |
| すること | 各パートをもう一方の言語に通訳する | 各発言を相手の言語に通訳する。発言ごとに方向が変わる |
| 話せる必要のある言語 | 訳出先の言語 | 両方の言語 |
| 設定 | 通訳までの文の数、パートの数 | 1 発言あたりの文の数、発言の回数 |

対話では、場面と話し手の説明、そして発言ごとに「誰が話しているか」
「どの言語に通訳するか」がページに表示されます。読み上げの声とマイクの言語は
発言ごとに自動で切り替わるので、ブラウザーに両方の言語の音声が必要です
(「音声 読み上げ」参照)。

最後に、パートまたは発言ごとの模範訳とコメント、全体へのコメントが表示され、
ダウンロードできます。

## 資料のアップロード

会話、就職面接、語彙練習、ディクテーションでは、履歴書、求人票、記事、
単語リストなどのファイルを使えます。

| ファイルの種類 | 対応 | 備考 |
|---|---|---|
| テキスト(`.txt`、`.md`、`.csv`) | ○ | |
| PDF | ○ | 選択できる文字が含まれていること。スキャンした PDF には文字がないので、ページの写真を画像としてアップロードする |
| Word `.docx` | ○ | 本文と表を読む。画像、ヘッダー、フッターは読まない |
| Word `.doc`(旧形式) | × | Word で開き、「名前を付けて保存」で `.docx` か PDF にする |
| 画像(`.png`、`.jpg`、`.webp`) | 会話と面接のみ | 画像を読めるチャットモデルが必要 |

ファイルはパソコンのメモリ上で読み取られ、保存されません。モデルに渡されるのは
文書の最初の 8,000 文字だけで、途中で切った場合はアプリが知らせます。

## 作文

書く練習をして、採点を受けます。

1. 言語とレベルを選びます。**先生からの課題**で始めるか、すでに書いたものが
   あれば**自分の作文**で始めます。
2. 作文を入力するか、アップロードします。テキスト、PDF、Word `.docx` のファイル、
   または手書きの作文の写真(4 枚まで)が使えます。アップロードした内容は
   入力欄に入るので、送信前に確認できます(読み違えられた手書きも直せます)。
3. 4 つの観点(内容、構成、語彙、文法)の評価、文章でのフィードバック、
   特に重要な訂正、そして作文の模範例が返ってきます。作文を直して
   もう一度チェックを受けることも、結果をダウンロードすることもできます。

長さ: 2,000 文字程度までを推奨します。それより長い作文も警告付きで
受け付けますが、小型のローカルモデルでは時間がかかり、後半のチェックが
甘くなることがあります。5,000 文字を超える作文は受け付けません。
2 回に分けてチェックしてください。

評価はモデルの判断であり、試験の点数ではありません。公式の成績としてではなく、
自分の作文を時間を追って比べるために使ってください。手書きには、画像を
読めるチャットモデルが必要です。

## 翻訳

文章を翻訳する練習をして、採点を受けます。

1. 言語の組み合わせ、難易度、文章の長さを選びます。**先生が用意した文章**で
   始めるか、原文と訳文の両方がすでにあれば**自分の文章と訳**で始めます。
2. 訳文を入力するか、アップロードします。テキスト、PDF、Word `.docx` のファイル、
   または手書きの写真(4 枚まで)が使えます。自分の文章を使う場合は、原文も
   入力・貼り付け・アップロードします。アップロードした内容は入力欄に入るので、
   送信前に確認できます。
3. 4 つの観点(正確さ、訳抜けのなさ、自然さ、文法と語彙)の評価、助言を含む
   フィードバック、特に重要な訂正、模範訳が返ってきます。訳文を直して
   もう一度チェックを受けることも、結果をダウンロードすることもできます。

長さ: 原文・訳文それぞれ 1,500 文字程度までを推奨します。それより長い場合は
警告付きで 3,000 文字まで受け付けます。作文より上限が低いのは、モデルが
2 つの文章を読んだうえで 3 つ目を書く必要があるためです。

## 聴解

読解と同じ練習を、耳で行います。先生が話し言葉の短い話、アナウンス、物語を
書き、アプリがそれを読み上げ、あなたは選択式の問題に答えます。

- 聞いている間、文章は表示されません。結果の画面で、答えと解説の横に
  表示されます。
- 何度でも再生でき、途中で止めたり、速度を変えたりできます。
- "Long"(長い)は話し言葉で約 2 分です。読解より文章は短めです。
- 声はブラウザーまたは音声サーバーのものを使うので(「音声 読み上げ」参照)、
  その言語でどんな声が使えるかによって質が変わります。

## スピーチ

短いスピーチをして、講評を受けます。声で行う作文のようなものです。

1. 言語、難易度、長さ(約 1 分、2 分、3 分)を選びます。**先生からの課題**
   (話題、場面、聞き手、盛り込む点)で始めるか、**自分の話題**で始めます。
2. スピーチを録音します。タイマーが目標時間に対する経過時間を示し、目標の
   1 分後に録音は自動で止まります。何度でも録り直せます。
3. アプリが、あなたの話した内容を文字に起こします。録音を聞き直し、
   聞き間違えられた箇所を直してから送信します。
4. 4 つの観点(内容、構成、言語、聞き手への効果)の評価、フィードバック、訂正、
   そして模範スピーチの原稿が返ってきます。原稿は読み上げさせることもできます。
   結果はダウンロードできます。

コーチは文字に起こした原稿をもとに講評しており、あなたの声を聞いていません。
そのため、発音、声、イントネーションは評価できません。アプリ自身が測るのは
スピーチの長さと話す速さで、どちらも結果に表示され、コーチのコメントの材料にも
なります。

## シャドーイング

文を聞き、自分で言い、アプリの音声認識がどの語を聞き取れたかを見ます。
聞き取れなかった語は強調表示され、何度でもやり直せます。記録されるのは
いちばん良かった回です。最後に、平均、聞き取られにくかった語、その語への
助言が表示されます。

- 文は先生が用意するか、自分の文章(テキスト、PDF、`.docx`)から作られます。
- **Hide the sentence**(文を隠す)にチェックを入れると、聞くだけで復唱します。
  文は 1 回目のあとに表示されます。
- これは発音の点数ではありません。音声認識は「何を言おうとしたか」を推測する
  ものなので、認識された語は「良い兆し」であって証明ではなく、
  **どう**発音したかは聞いていません。認識されなかった語は、練習する価値が
  あります。
- 同じ語に複数の書き方がある言語(日本語の漢字とかななど)では、正しく
  発音した語でも、認識結果の表記が違うと「認識されなかった」と表示される
  ことがあります。

## 読解

先生が文章と、それについての選択式問題(4 択、最大 10 問)を作ります。
語学の検定試験の読解問題のような形式です。

1. 言語、難易度、文章の長さ、問題数、問題の難しさを選びます。
   **Straightforward**(素直な問題)は、該当する文を見つければ答えられます。
   **Tricky**(ひねった問題)は、正解を別の言葉で言い換え、不正解の選択肢に
   本文の表現をそのまま使うので、単語を照らし合わせるだけでは解けません。
   "Long"(長い)は A4 用紙約 1 枚分(約 500 語、日本語や中国語などでは
   約 1,000 文字)です。
2. 先に文章が表示されるので、問題の準備中に読み始められます。
3. 答えを選んで送信します。得点、正解とその理由、そして間違えた問題に
   ついては、選んだ選択肢がなぜ違うのかが表示されます。結果は
   ダウンロードできます。

Tricky の問題には確認の手順が入ります。モデルが、想定された正解を
知らされないまま本文から各問題を解き、同じ答えになった問題だけが残ります。
これであいまいな問題の大半は除かれますが、そのぶんモデルの呼び出しが
1 回増えます。

採点するのはモデルではなくアプリ自身で、選択肢の順番は入れ替えられます。
それでも小型のローカルモデルは、「正解」に議論の余地がある問題をまれに
作ることがあります。問題がおかしいと感じたら、本文を信じてください。
形式の整っていない問題は捨てられるので、指定より少ない問題数になることが
あります。

## 文法ドリル

文法項目についての短い練習です。

1. 言語と難易度を選び、文法項目を指定します(例: "past simple or present
   perfect")。空欄にすると、先生がレベルに合った項目を選びます。
2. 練習の種類を選びます。**Fill in the blank**(穴埋め: 文を完成させる)、
   **Correct the mistake**(誤文訂正: 誤りを 1 つ含む文を書き直す)、
   または Mixed(両方)。最大 10 問です。
3. 得点と、問題ごとにあなたの答え、正解、その根拠となる規則、あなたの答えの
   どこが違っていたかのコメントが表示されます。

採点の方法は語彙練習と同じです。アプリ自身が、大文字・小文字と句読点を
無視して、あなたの答えを正解と照合します。一致しなかった答えは先生に見せ、
それでも正しければ正解として認められます。形式の整っていない問題
(空欄がない、正解がはっきりしない)は捨てられるので、指定より少ない問題数に
なることがあります。

## 履歴と間違いの復習

**Progress** セクションには、これまでにやったことが残ります。上達の様子を
確かめたり、間違えたところに戻ったりできます。

**History**(履歴)には、終えたセッションが日付、言語、得点とともに並びます。
小さな表に、練習の種類ごとのセッション数、平均点、直近 5 回の平均が
表示されます(2 つの平均を比べると、伸びているかどうかがわかります)。
*Open* を押すと、「Download result」のファイルと同じ内容で結果全体が
もう一度表示され、ダウンロードや削除ができます。

**My mistakes**(間違いリスト)には、復習すべき項目が 1 つずつ集まります。

| どこから | 集められるもの |
| --- | --- |
| 語彙練習 | 間違えた単語、飛ばした単語 |
| 文法ドリル | 間違えた問題、飛ばした問題 |
| 読解・聴解 | 間違えた問題 |
| ディクテーション | 聞き落としのあった文 |
| 作文、翻訳、スピーチ | 先生による訂正 |

同じ間違いをもう一度すると、二重に載るのではなく回数が数えられます
("wrong 3 times")。**Practise the words in Vocabulary** を押すと、間違えた
単語で語彙練習が始まります(最大 50 語、言語の組み合わせは一度に 1 つ)。
正しい訳がすでに保存されているので、モデルは使いません。そこで正しく
訳せた単語は、自動的に「覚えた」(learned)になります。そのほかの項目は、
手動で「覚えた」にするか、削除します。

保存場所: パソコン上のデータベースファイル 1 つ、`data/history.db` です
(SQLite。Python に付属しているので、インストールは不要)。

- ブラウザーの中**ではない**ので、ブラウザーのデータを消しても残り、
  このパソコンのどのブラウザーからも同じ履歴が見えます。
- 保存されるのは文字だけです(得点、あなたの答え、訂正、フィードバック)。
  録音は保存されません。結果 1 件は数キロバイトです。
- パソコンの外には出ません。`data/` は git の対象外です。
- バックアップするには、このファイルをコピーします。最初からやり直すには、
  アプリを止めた状態でファイルを削除するか、ページの削除ボタンを使います。
- 別の場所に置きたい場合は、`.env` に `HISTORY_DB` を設定します。
- 保存をやめるには、History のページで "Save my results in the history" の
  チェックを外します(ブラウザーごとに記憶されます)。

このアプリは、**1 つのインストールにつき学習者 1 人**を前提にしています。
ユーザーアカウントはないので、同じアプリを使う人は全員、1 つの履歴を
共有します。

## 単語リスト作成

単語リストを作って CSV ファイルとして保存します。Excel で開けるほか、
Anki などの暗記カードツールに取り込めます。

| 列 | 内容 |
|---|---|
| 1 | 学習している言語の単語またはコロケーション |
| 2 | 読み・発音(日本語はひらがな、中国語はピンイン、ラテン文字の言語は IPA など) |
| 3 | 説明用に選んだ言語での訳 |
| 4 | 任意: 例文とその訳。あれば補足(文体、ニュアンス、よくある間違い) |

使い方は 2 通りです。

- **リストを作る:** 言語、難易度、語数(最大 100)を選び、ほしい内容を
  プロンプトに書きます。
- **自分のリストを整える:** 1 行に 1 語(または 1 句)を書いたテキスト
  ファイル、選択できる文字を含む PDF、または `.docx` をアップロードします。
  体裁は整っていなくても構いません。読みや意味や注が抜けていても、
  混ざっていても大丈夫です。すべての行が完全な項目になって返ってきます。
  "Number of words"(語数)は無視されます。使われるのは最大 100 行で、
  ファイルがそれより長いときはアプリが警告します。

4 列目は省略できます。フォームでチェックを外すと最初から作られないので、
そのぶん速くなります。できあがったリストの上でチェックを外し、4 列目なしで
もう一度ダウンロードすることもできます。Vocabulary タブで単語リストとして
アップロードするなら、3 列のリストのほうが向いています。小型モデルが読む
文章が少なくて済むからです。

ファイル形式はダウンロードボタンの横で選びます。選択は記憶され、同じリストを
別の形式でもう一度ダウンロードできます。

| 形式 | 向いている用途 | 備考 |
|---|---|---|
| CSV(既定) | Excel、Anki などの暗記カードツール | 上の 4 列 |
| テキスト | 読む、印刷する、メモに貼る | 1 語ごとに番号付きのまとまり |
| Word(.docx) | 編集と印刷 | 横向きのページに表 |
| PDF | 共有と印刷 | ブラウザーの印刷画面が開くので、プリンターとして「PDF に保存」(または "Microsoft Print to PDF")を選ぶ。この方法なら、どの文字もパソコンのフォントで正しく表示される |
| JSON | ほかのプログラム | 例文、その訳、補足が別々の項目になっている |

リストは 10 項目ずつ作られるので、増えていく様子を見ながら、止めたり、
続けたり、できた分だけダウンロードしたりできます。ローカルモデルでは、
100 項目に数分かかることがあります。

勉強に使う前に、結果を確かめてください。小型のローカルモデルは、読みや
ニュアンスを間違えることがあります。モデルが完成させられなかった項目は
色付きで表示され、元の行がそのまま残ります。

## 手書きのディクテーション

Dictation で **How you write: By hand** を選びます。各文を聞いて紙に書き、
最後にそのページの写真かスキャン(PNG、JPEG、WebP。4 ページまで)を
アップロードします。

1. チャットモデルが手書きを読み取ります。モデルには元の文章を見せないので、
   あなたの間違いをこっそり直すことはできません。
2. 読み取られた内容が表示されるので、採点の前に読み違いを直せます。
3. あとは入力したディクテーションと同じように採点されます。

これには、画像を読めるチャットモデルが必要です(たとえば Ollama の
`gemma4:e4b`)。写真は送信前にブラウザーの中で縮小され、保存されません。
きれいに読み取らせるには、濃いインクで、行間をあけて書き、明るい場所で
まっすぐ撮影してください。

## 音声 読み上げ

聞く場面のある機能(会話、就職面接、通訳、シャドーイング、聴解、
ディクテーション、語彙練習の音声モード、模範スピーチ)には、すべて音声が
必要です。音声を用意する方法は 2 つあり、`.env` の `TTS_PROVIDER` で選びます。

| | `browser`(既定) | `openai_compatible` |
|---|---|---|
| 話すもの | ブラウザーと Windows に内蔵の音声 | ローカルまたはクラウドの音声サーバー |
| インストール | 不要。または Windows の言語パックを追加 | 音声サーバー、またはクラウドのアカウント |
| 品質 | 音声による。基本的なものから良いものまで | モデルによる。より自然なことが多い |
| プライバシー | Windows の音声ならローカル(下の注を参照) | ローカルサーバーならパソコンの中。クラウドなら文章が事業者に送られる |

### ブラウザーの音声

Chrome か Edge を使ってください。アプリは、セッションの言語に合う音声を
一覧にして、選べるようにします。

その言語の音声がないと表示された場合は、Windows に追加します。
**設定 > 時刻と言語 > 言語と地域 > 言語の追加** で言語を選び、
**音声合成** にチェックが入ったままにします。そのあとブラウザーを
再起動してください。

プライバシーについての注: 名前に "Online"、"Natural"、"Google" を含む音声は、
その会社のサーバーで作られるため、読み上げる文がそこに送られます。
これらの語を含まない音声は、パソコンの中で動きます。

### 音声サーバー

OpenAI 形式の `/audio/speech` エンドポイントを持つサーバーなら、どれでも
使えます。クラウドの音声 API でも、別途それ自身のライセンスでインストールする
ローカルの音声サーバーでも構いません。`.env` に次を設定します。

```ini
TTS_PROVIDER=openai_compatible
TTS_BASE_URL=<サーバーの API アドレス。多くは /v1 で終わる>
TTS_MODEL=<音声モデルの名前>
TTS_VOICE=<声の名前。サーバーが必要とする場合>
TTS_API_KEY=<あなた自身のキー。ローカルサーバーなら空欄>
```

## マイク 音声認識

会話、就職面接、通訳、スピーチ、シャドーイング、語彙練習の音声モードでは、
マイクであなたの声を録音し、それを文字にします。方法は `.env` の
`STT_PROVIDER` で選びます。

| | `faster_whisper`(既定) | `openai_compatible` |
|---|---|---|
| 聞くもの | パソコン上で動く Whisper モデル | ローカルまたはクラウドの文字起こしサーバー |
| インストール | `pip install -r requirements-voice.txt` | サーバー、またはクラウドのアカウント |
| プライバシー | 録音はパソコンの中にとどまる | クラウドなら録音が事業者に送られる |
| 速さ | 最近の CPU で 1 回の発言につき数秒 | サービスによる |

### ローカルの Whisper

1. 有効化した環境の中で、一度だけインストールします。

   ```powershell
   pip install -r requirements-voice.txt
   ```

2. 初めてマイクを使うときに、モデル(`small` で約 0.5 GB)が自動で
   ダウンロードされます。その最初の 1 回は遅く、2 回目からは速くなります。

`.env` の任意の設定:

| 設定 | 既定値 | 意味 |
|---|---|---|
| `STT_MODEL` | `small` | `base` は速いが精度が下がる。`medium` は遅いが精度が上がる |
| `STT_DEVICE` | `cpu` | `cuda` は NVIDIA の GPU を使うが、NVIDIA の追加ライブラリが必要で、グラフィックメモリをチャットモデルと分け合うことになる。`cpu` が無難 |

### 文字起こしサーバー

```ini
STT_PROVIDER=openai_compatible
STT_BASE_URL=<サーバーの API アドレス。多くは /v1 で終わる>
STT_MODEL=<文字起こしモデルの名前>
STT_API_KEY=<あなた自身のキー。ローカルサーバーなら空欄>
```

### マイクの使い方

- アプリは `http://localhost:8000` で開いてください(ほかのアドレス経由では
  なく)。ブラウザーがマイクを許可するのは、`localhost` か安全なサイトだけです。
- 最初に、ブラウザーがマイクの使用許可を求めます。
- マイクのボタンを押して話し、話し終えたらもう一度押します。
- Conversation と Job interview では、代わりに **Hands-free** にチェックを
  入れることもできます。相手が話し終えるとアプリが聞き取りを始め、あなたが
  2 秒間黙ると自動で止まります。考えながら間を置きたい人は、チェックを
  外したままにしてください。その場合、ボタンを押すまで何も送られません。
- この 2 つの機能では、モデルが答えを書いている途中から、1 文ずつ
  読み上げが始まります。答え全体を待つ必要はありません。

知っておきたいこと: 音声認識は、あなたが「言おうとした」と判断した内容を
書き起こします。発音は評価できず、小さな言い間違いを整えてしまうこともあるので、
フィードバックは語彙、文法、内容についてのものになります。

## 制限事項

先生は言語モデルで、ローカル構成では小型のモデルです。根気よく付き合ってくれる
練習相手ではあっても、試験官ではありません。間違いを見逃すことも、正しいものを
「訂正」してしまうことも、規則を単純化しすぎて説明することもあります。
フィードバックがおかしいと感じたら、辞書や文法書で確かめてください。
大きいモデル(やクラウドのモデル)ならこうした誤りは減りますが、ゼロには
なりません。

アプリ全体の制限:

- **音声認識は推測する。** いちばんありそうな語を書き起こすので、正しく言った
  語を聞き間違えることがあります(短い語、固有名詞、同音異義語、強いなまりで
  起きやすい)。逆に、実際の言い間違いを黙って直してしまうこともあります。
  発音、強勢、イントネーションは一切聞いていません。
- **読み上げは読み間違えることがある。** 合成音声は、数字、略語、固有名詞、
  そして日本語では漢字の読みを間違えることがあります。
- **質は言語によって違う。** モデルも、音声も、音声認識も、広く使われている
  言語で最もよく働き、そうでない言語では弱くなります。
- **評価は試験の点数ではない。** 自分の成果を時間を追って比べるために使って
  ください。同じ文章でも、2 回目には少し違う評価になることがあります。
- **長い文章。** ローカルモデルが一度に読める量には限りがあります
  (「コンテキストウィンドウ」参照)。アプリは警告を出しますが、モデルに
  それ以上読ませることはできません。
- **学習者 1 人、パソコン 1 台。** アカウントも、端末間の同期もありません。
  画面は英語のみです。
- **進行中のセッションはメモリの中にある。** セッションの途中でアプリを
  止めたり再起動したりすると、そのセッションは失われます(終えた結果は
  履歴に残ります)。
- **速さ。** ローカルモデルでは一つひとつの処理に数秒かかり、長い作業
  (100 語のリスト、10 問付きの長文)には数分かかります。

機能ごとの制限:

| 機能 | 気をつけること |
|---|---|
| 会話、就職面接 | フィードバックは書き起こしに基づくので、正しく言った語が聞き間違えられて「訂正」されることがある。発音は評価されない。Hands-free では 2 秒黙ると発言が終わり、周囲の雑音があるとマイクが開いたままになることがある。面接官は、あなたが渡した情報以外に、実際の会社や仕事のことを知らない |
| 通訳 | あなたの通訳は書き起こしから評価される。「模範訳」は良い訳の一例であって唯一の正解ではなく、もう一方の言語での質はモデルによる。対話では両方の言語の音声が必要 |
| スピーチ | 発音、声、身ぶりは評価されない。話す速さは書き起こしから数えるので、認識の誤りで少し変わる |
| シャドーイング | 発音の点数ではなく、音声認識が聞き取れた語を示すもの。正しく言った語が「聞き取れなかった」とされることがあり(漢字とかなのように表記が複数ある言語で起きやすい)、うまく言えなかった語が通ってしまうこともある |
| 聴解 | 練習の質は、その言語で使える音声による。問題がまれにあいまいなことがある |
| 語彙練習(入力) | すぐに正解と判定されるのは登録された訳だけ。それ以外の正しい訳は先生の確認しだいで、厳しすぎることも甘すぎることもある。単語は文脈なしで出題される |
| 語彙練習(音声) | 文脈のない単語 1 つは、音声認識にとって最も難しい。正しく発音しても、違う語として、あるいは同じ音の別の語として書き起こされることがある。送信する前に解答欄を確かめ、必要なら直すこと |
| 単語リスト作成 | 読み、ニュアンス、例文に誤りが含まれることがある。覚える前にリストを確認すること。1 つのリストは最大 100 項目 |
| ディクテーション | 句読点と大文字・小文字は採点されない。同じ語でも別の正しい書き方(数詞の代わりに数字、漢字の代わりにかな)をすると、違うものとして扱われる。手書きは読み違えられることがあるので、確認欄を見ること |
| 作文、翻訳 | 評価はモデルの意見。挙げられるのは特に重要な誤りだけで、すべてではない。模範例は一つの可能性にすぎない。長さの上限がある |
| 読解 | 「正解」に議論の余地があることがまれにある(主に Tricky の問題と小型モデル)。指定より少ない問題数になることがある |
| 文法ドリル | モデル自身の正解が間違っていれば、採点も間違う。別の正しい答えが認められるかは確認しだい。解説は短く、例外に触れないことがある |
| 履歴と間違いの復習 | 保存されるのは、この機能が追加されたあとに終えたセッションだけ。同じ間違いと見なされるのは、文字が完全に一致する場合のみ。文章によるフィードバック(会話、通訳、シャドーイング)は復習項目にならない |
| アップロード | 使われるのは文書の最初の 8,000 文字だけ。スキャンした PDF と旧形式の `.doc` は読めない。写真には、画像を読めるモデルが必要 |

## パソコンの外に出るもの

| 構成 | 何が、どこに送られるか |
|---|---|
| ローカル(Ollama、ローカルの Whisper、名前に "Online"・"Natural"・"Google" を含まない音声) | 何も送られない。文章、録音、アップロードしたファイル、履歴は、すべてパソコンの中にとどまる |
| 名前に "Online"・"Natural"・"Google" を含むブラウザーの音声 | 読み上げられる文が、その会社のサーバーに送られる |
| クラウドのチャット、音声合成、文字起こしのサービス | その部分が扱うもの。チャットなら文章とアップロードしたファイル、音声合成なら読み上げる文、文字起こしなら録音。事業者のプライバシー規約が適用される |

インストールのときに、Python のパッケージ、Ollama のモデル、Whisper のモデルが
一度だけダウンロードされます。アプリ自身は統計を集めず、追跡の仕組みも
含みません。待ち受けるのは自分のパソコン(`localhost`)だけなので、
ネットワーク上のほかの機器からは開けません。

## トラブルシューティング

メッセージは画面に英語で表示されます。

| メッセージ・症状 | 対処 |
|---|---|
| "Could not reach the model server"(モデルのサーバーに接続できない) | Ollama を起動する(スタートメニューで "Ollama" を検索)。または `LLM_BASE_URL` を確認する |
| "Model ... was not found"(モデルが見つからない) | `ollama pull <モデル>` を実行する。または `.env` の `LLM_MODEL` を直す |
| "The model took too long to answer"(応答に時間がかかりすぎた) | 最初のリクエストはモデルの読み込みがあるので遅い。やり直すか、`LLM_TIMEOUT` を大きくする |
| "rejected the API key"(API キーが拒否された) | `.env` の `LLM_API_KEY` を確認する |
| "did not return a usable word list" / "dictation text"(使える単語リスト・書き取り文が返ってこなかった) | やり直す。繰り返すなら、より大きいモデルを試す |
| "This browser has no voice for ..."(その言語の音声がない) | Windows に言語を追加する(「音声 読み上げ」参照)。または音声サーバーを使う |
| "Local speech recognition is not installed"(ローカルの音声認識が入っていない) | 有効化した環境で `pip install -r requirements-voice.txt` を実行する |
| "Could not load the Whisper model"(Whisper モデルを読み込めない) | 最初の使用時は、ダウンロードのためにインターネット接続が必要。`STT_MODEL` を確認する |
| "The microphone is blocked or missing"(マイクがブロックされているか、見つからない) | アドレスバーの鍵またはマイクのアイコンを押して、マイクを許可する。Windows の 設定 > プライバシーとセキュリティ > マイク も確認する |
| "No words were recognised"(語が認識されなかった) | マイクに近づいて話す。Windows が正しい入力デバイスを使っているか確認する |
| 相手の声が聞こえない | パソコンの音量を確認する。Voice の一覧で別の声を選ぶ。または Edge を試す |
| "Reading handwriting needs a chat model that can read images"(手書きの読み取りには画像を読めるモデルが必要) | 画像に対応したチャットモデルを使う。または入力で書き取る |
| 手書きがうまく読み取られない | 写真を撮り直す(まっすぐ、ピントを合わせ、明るく)。残った読み違いは確認欄で直す |
| ディクテーションの音が出ない | パソコンの音量を確認する。Voice の一覧で別の声を選ぶ。または Edge を試す |

## 未対応の項目

確認できている範囲を超えて期待されることのないよう、わかっている不足を
挙げておきます。

- **クラウドモデルでの通しのテストは、まだ行っていません。** アプリは
  OpenAI 形式の API を通じてモデルと通信します。この部分は Ollama と、
  自動テスト用の擬似サービスでは動作を確認していますが、実際のクラウド事業者
  (チャット、音声合成、文字起こし)に対して全機能を動かしたことはまだ
  ありません。事業者によって、モデルが受け付けるオプションなどに小さな違いが
  ある可能性があります。
- **macOS では未確認です。** 上のインストール手順は、各ツールのドキュメントを
  もとに書いたもので、Mac で試したものではありません。
- **ブラウザーテストは Linux でのみ実行されています**(自動チェックの中で)。
  また、アップロード(文書と写真)、就職面接、2 人の通訳、単語リストの Word・
  PDF 出力、Hands-free モードは、まだテストの対象になっていません。
- **表記の違い**(漢字とかな、数字と数詞)は、ディクテーションと
  シャドーイングで、まだ同じ語として扱われません。
- **Chrome と Edge 以外のブラウザー**(Firefox、Safari)は試していません。

## 開発者向け

### プロジェクトの構成

```
app/
  main.py            入口。API とブラウザー用の画面を提供する
  config.py          環境変数 / .env から読む設定
  context.py         リクエストごとの設定(フィードバックの言語)と学習者への注意
  providers/
    base.py          3 つのインターフェース: ChatProvider, SpeechToText, TextToSpeech
    openai_compatible.py   Ollama と OpenAI 形式の API 用の頭脳・耳・口
    faster_whisper.py      耳: ローカルの Whisper(任意でインストール)
    factory.py       設定で指定されたプロバイダーを選ぶ
  features/
    talk.py          機能 1・2(会話、就職面接)
    interpreter.py   機能 3
    vocabulary.py    機能 4
    dictation.py     機能 5
    speech.py        音声の共通エンドポイント(文字起こし、音声合成)
    materials.py     アップロードされた PDF・Word ファイルから文字を読む
    wordlist.py      機能 6(単語リスト作成)
    essay.py         機能 7(作文)
    reading.py       機能 8・10(読解、聴解)
    shadowing.py     機能 11(シャドーイング)
    public_speaking.py   機能 12(スピーチ)
    grammar.py       機能 13(文法ドリル)
    history.py       履歴と間違いの復習(data/ の中の SQLite ファイル)
    translation.py   機能 9(翻訳)
    handwriting.py   写真から手書きを読む(ディクテーションと作文)
  textutils.py       文字列の共通処理(答えの照合、ディクテーションの採点)
  static/            ブラウザー用の画面(素の HTML、CSS、JavaScript)
.github/workflows/   push のたびに GitHub が実行する自動チェック
LICENSE              ライセンス(「ライセンス」参照)
USER_MANUAL.md       専門知識のない人向けのかんたんなインストールガイド
README.ja.md, USER_MANUAL.ja.md   両文書の日本語版
tests/               モデルなしで動くテスト(偽のプロバイダーを使う)
  browser/           実際のブラウザーでページを操作するテスト
data/                ローカルのユーザーデータ。git の対象外
```

各機能は必ず `providers/base.py` のインターフェースを使い、特定の事業者を
直接呼び出してはいけません。プロバイダーを追加するには、新しいファイルで
インターフェースを実装し、`providers/factory.py` に登録します。

### テスト

テストは 2 種類あり、どちらも Ollama、GPU、マイクを必要としません。

| | 速いテスト(`tests/`) | ブラウザーテスト(`tests/browser/`) |
|---|---|---|
| 確認するもの | 各機能の裏側の Python コード | ページそのもの。実際のブラウザーが全機能を操作する |
| モデルの代わり | テスト内の偽のプロバイダー | 擬似のモデル・音声・音声認識サーバー(`tests/browser/fake_services.py`) |
| 追加のインストール | なし | `playwright` とブラウザー(インストール済みの Chrome か Edge で足りる) |
| 所要時間 | 数秒 | 約 30 秒 |

```powershell
pip install -r requirements-dev.txt
python -m pytest -m "not browser"      # 速いテストだけ
```

ブラウザーテストのために、一度だけインストールします。

```powershell
pip install -r requirements-browser.txt
```

そのあと:

```powershell
python -m pytest                       # すべて
python -m pytest tests/browser         # ブラウザーテストだけ
```

- ブラウザーのウィンドウは表示されません。テストがページを操作する様子を
  見たい場合は、先に(同じ PowerShell ウィンドウで)
  `$env:BROWSER_TESTS_HEADED = "1"` を実行します。
- テストは、Playwright 付属の Chromium、インストール済みの Chrome、Edge の
  順に探します。Playwright の Chromium をダウンロードするには
  `python -m playwright install chromium`。ほかの Chromium 系ブラウザーを
  使うには、そのフルパスを `BROWSER_TESTS_CHROME` に設定します。
- `playwright` パッケージがない場合、ブラウザーテストは失敗ではなく
  *スキップ*として報告されます。
- テストは、空いているポートでアプリのコピーを自分で起動し、一時的な
  履歴ファイルを使います。あなたの `.env`、Ollama、`data/history.db` は
  使われず、起動中のアプリとぶつかることもありません。
- 擬似サーバーは、プロンプトに含まれる語句で、どのプロンプトかを見分けます。
  `app/features/` のプロンプトの文言を変えたら、`fake_services.py` の対応する
  語句も合わせて変えてください(変えるまで、その機能のテストは失敗します)。

### GitHub の自動チェック

`.github/workflows/checks.yml` により、main ブランチへの push と
プルリクエストのたびに、GitHub が自分のマシンで 3 つのチェックを実行します。

| チェック | 内容 | 失敗する場合 |
|---|---|---|
| Secret scan(秘密情報のスキャン) | gitleaks が、最新のコミットだけでなく**すべてのコミット**を読む | キーやパスワードらしきものが一度でもコミットされていた |
| Tests(テスト) | 速いテストを Linux と Windows、Python 3.11 と 3.13 で実行 | テストが失敗した |
| Browser tests(ブラウザーテスト) | ブラウザーテストを Linux で実行 | ページが動かなくなった |

結果は、コミットの横に緑のチェックか赤の × として表示されます。リポジトリの
**Actions** タブでは、各ステップの出力を読めます。チェックには秘密情報も、
モデルも、GPU も不要で、公開リポジトリなら無料です。

知っておくべき点が 2 つあります。

- 秘密情報のスキャンが動くのは push の**あと**なので、その時点でキーは
  すでに GitHub 上にあります。これは、最初の防衛線である各コントリビューターの
  パソコン上の `pre-commit` スキャナー(下の規則 4)を補う「安全網」です。
  スキャンが赤になったら、そのキーは漏れたものとして扱い、無効にして
  新しく作り直してください。
- 赤い × が出ても、それだけでは何も止まりません。チェックを必須にするには、
  リポジトリの所有者が GitHub で一度だけ規則を有効にします。
  **Settings > Rules > Rulesets > New branch ruleset** で既定のブランチを
  対象にし、**Require a pull request before merging** と
  **Require status checks to pass** にチェックを入れ、チェックを名前で
  追加します(ワークフローが一度実行されたあとに選べるようになります)。
  それ以降、プルリクエストは、すべてが緑のときだけマージできます。

### コントリビューター向けのセキュリティ規則

1. **秘密情報を絶対にコミットしない。** キーを置くのは、git の対象外である
   `.env` の中だけです。`.env.example` には仮の値しか書きません。
2. **ユーザーのデータを絶対にコミットしない。** 録音、アップロード、
   セッションの記録は、git の対象外である `data/` に置きます。
3. **キーはサーバー側にとどめる。** `app/static/` の中のものが、キーを含んだり
   受け取ったりしてはいけません。
4. クローンしたら一度だけ、**秘密情報のスキャナーを有効にする。** キーらしき
   ものを含むコミットを止めてくれます。

   ```powershell
   pre-commit install
   ```

5. 誤ってキーをコミットしてしまった場合、あとのコミットで消すだけでは
   足りません。git には履歴が残るからです。事業者側でそのキーを無効にし、
   新しいキーを作ってください。
